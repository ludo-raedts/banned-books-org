# Extend research — give thin sourced histories more dated, sourced events

Each book in data/redactie/extend/books.json has a sourced one-sentence history (`current_text`, already verified against sources). Find 1–4 ADDITIONAL concrete, dated censorship events about the BOOK itself (not a film, anime, stage or comic adaptation) in sources you fetch and read in full (Bash: curl -sL -A "Mozilla/5.0" URL → plain text via python3; Wikipedia action=raw; other-language Wikipedias; news, court judgments, gazettes, libraries/universities, ALA/NCAC/PEN/Index/Freedom to Read, Papers Past, Trove, Gallica...). `verified_ban_rows` are leads for where to look, NOT facts you may use without a quote.
Output per book (JSON array in your findings file): { "slug", "entry": { "slug", "text", "sources": [ {"url","title","quote"} ], "note" } | null, "no_entry_reason" }.
 - `text` = the FULL new history: keep every fact and year of `current_text` (reworded if you like) and add the new events, chronological, 2–5 plain sentences, first sentence with author + title + place + year when supported. No outside knowledge, no judgement adjectives; keep the measure accurate (ban / challenge / removal / restriction / prosecution / Index listing / seizure).
 - `sources` = ONLY the NEW quotes (the old ones stay in the database). Each quote: copied EXACTLY from the plain text of the page, 60–400 chars, one passage, no ellipses.
 - A mechanical verifier publishes only if each quote occurs literally on the page as plain `fetch` returns it (HTML tags stripped, named entities decoded, numeric entities like &#8220; NOT decoded: avoid quotes on text containing them; pages that need JS or return 403 fail), every 3–4 digit number and capitalised name in `text` occurs in the old text, the old quotes, the new quotes or the title/author, and every year of the old text is kept. Do not start sentences with words like 'Another'/'One'/'Several' (treated as names).
 - Run the verifier yourself until your entries show ✓: `pnpm tsx --env-file=.env.local scripts/publish-hand-sourced-history.ts --extend --file=<your findings entries file>` — NOTE the verifier reads an array of entries, so write your final entries ALSO as a plain array of the `entry` objects to data/redactie/extend/entries-<N>.json (dry-run is read-only).
 - If no safe new dated event exists after real effort, return entry null with the reason. Never invent; missing evidence is not evidence of falsity.
Do not touch the database or any other file; never run with --apply. Reply with: n entries passing, n null.
